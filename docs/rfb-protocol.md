# RFBプロトコル仕様ノート (RFC 6143)

本ドキュメントはRFC 6143 (The Remote Framebuffer Protocol) の詳細分析である。
libopenvncライブラリの実装に必要な全情報をまとめる。

- 原文: https://datatracker.ietf.org/doc/html/rfc6143
- 発行: 2011年3月 (Informational)
- 著者: Tristan Richardson, John Levine (RealVNC Ltd)

---

## 1. プロトコル概要

RFB (Remote Framebuffer) はリモートGUIアクセスのためのシンプルなプロトコルで、VNCが使用する。

### 設計原則

- **シンクライアント**: クライアント側の要件を最小限に
- **ステートレス**: 切断・再接続してもUI状態が保持される
- **デマンドドリブン**: クライアントが更新を要求し、サーバは自動プッシュしない
- **非同期**: ハンドシェイク後は双方が任意のタイミングでメッセージ送信可能

### 用語

| 用語 | 説明 |
|------|------|
| RFBクライアント/ビューア | リモート側。画面表示・キーボード・マウスを操作 |
| RFBサーバ | フレームバッファの変更元。画面を提供する側 |

### ポート

| 用途 | ポート |
|------|--------|
| 標準接続 | 5900 (IANA割当済) |
| 複数サーバ | 5900+N |
| HTTP (ブラウザクライアント) | 5800 |
| リバース接続 (クライアントリッスン) | 5500 |

## 2. データ型

| 型 | サイズ | 説明 |
|----|--------|------|
| U8 | 1バイト | 符号なし8ビット整数 |
| U16 | 2バイト | 符号なし16ビット整数 |
| U32 | 4バイト | 符号なし32ビット整数 |
| S8 | 1バイト | 符号付き8ビット整数 |
| S16 | 2バイト | 符号付き16ビット整数 |
| S32 | 4バイト | 符号付き32ビット整数 |
| PIXEL | bits-per-pixel / 8 バイト | ピクセル値 |

**バイトオーダー**: マルチバイト整数はすべてビッグエンディアン（ネットワークバイトオーダー）。
ただしピクセル値自体はPIXEL_FORMATのbig-endian-flagに従う。

## 3. プロトコルフェーズ

```
┌─────────────────────────┐
│ 1. ハンドシェイクフェーズ │ ← バージョン + セキュリティ
├─────────────────────────┤
│ 2. 初期化フェーズ        │ ← ClientInit + ServerInit
├─────────────────────────┤
│ 3. 通常プロトコル        │ ← 非同期メッセージ交換
└─────────────────────────┘
```

## 4. ハンドシェイクフェーズ

### 4.1 バージョンネゴシエーション

サーバとクライアントがプロトコルバージョンを交換する。

#### メッセージフォーマット (12バイト固定)

```
"RFB xxx.yyy\n"
```

例: `RFB 003.008\n` (hex: `52 46 42 20 30 30 33 2e 30 30 38 0a`)

#### フロー

```
サーバ → クライアント: ProtocolVersion (サーバがサポートする最高バージョン)
クライアント → サーバ: ProtocolVersion (使用するバージョン, サーバ以下)
```

#### バージョン一覧

| バージョン | 文字列 | 備考 |
|------------|--------|------|
| 3.3 | `RFB 003.003\n` | 初期版 |
| 3.7 | `RFB 003.007\n` | セキュリティネゴシエーション追加 |
| 3.8 | `RFB 003.008\n` | エラーハンドリング改善、RFC標準化版 |

不明な3.xバージョンは3.3として扱う。

### 4.2 セキュリティハンドシェイク

#### RFB 3.8 (標準)

```
サーバ → クライアント:
┌─────────┬──────┬────────────────────────────┐
│ バイト数 │ 型   │ フィールド                  │
├─────────┼──────┼────────────────────────────┤
│ 1       │ U8   │ number-of-security-types    │
│ 可変    │ U8[] │ security-types (リスト)      │
└─────────┴──────┴────────────────────────────┘

クライアント → サーバ:
┌─────────┬──────┬────────────────────────────┐
│ バイト数 │ 型   │ フィールド                  │
├─────────┼──────┼────────────────────────────┤
│ 1       │ U8   │ security-type (選択した型)   │
└─────────┴──────┴────────────────────────────┘
```

`number-of-security-types` が0の場合は接続失敗:

```
┌─────────┬──────┬────────────────────────────┐
│ バイト数 │ 型   │ フィールド                  │
├─────────┼──────┼────────────────────────────┤
│ 4       │ U32  │ reason-length               │
│ 可変    │ U8[] │ reason-string               │
└─────────┴──────┴────────────────────────────┘
```

その後サーバが接続を閉じる。

#### RFB 3.3

サーバが一方的にセキュリティタイプを選択:

```
サーバ → クライアント:
┌─────────┬──────┬────────────────────────────┐
│ バイト数 │ 型   │ フィールド                  │
├─────────┼──────┼────────────────────────────┤
│ 4       │ U32  │ security-type (0,1,2のいずれか) │
└─────────┴──────┴────────────────────────────┘
```

0の場合は接続失敗 (reason-stringが続く)。

### 4.3 セキュリティタイプ

#### None (タイプ1) — 認証なし

認証不要。RFB 3.8ではSecurityResultメッセージへ進む。
RFB 3.3/3.7ではSecurityResultなしで直接初期化フェーズへ。

#### VNC認証 (タイプ2) — DESチャレンジレスポンス

```
サーバ → クライアント:
┌─────────┬──────┬────────────────────────────┐
│ バイト数 │ 型   │ フィールド                  │
├─────────┼──────┼────────────────────────────┤
│ 16      │ U8[] │ challenge (ランダム)         │
└─────────┴──────┴────────────────────────────┘

クライアント → サーバ:
┌─────────┬──────┬────────────────────────────┐
│ バイト数 │ 型   │ フィールド                  │
├─────────┼──────┼────────────────────────────┤
│ 16      │ U8[] │ response (DES暗号化済み)     │
└─────────┴──────┴────────────────────────────┘
```

**認証手順:**
1. サーバが16バイトのランダムチャレンジを送信
2. クライアントがパスワードをDES鍵として使い、チャレンジを暗号化
3. パスワードは8文字に切り詰めまたはNULLパディング
4. クライアントが16バイトのレスポンスを送信
5. SecurityResultへ進む

**注意:** 暗号学的に脆弱。信頼できないネットワークでは使用すべきでない。

### 4.4 SecurityResult

RFB 3.8で全セキュリティタイプに対して送信される。

```
サーバ → クライアント:
┌─────────┬──────┬────────────────────────────┐
│ バイト数 │ 型   │ フィールド                  │
├─────────┼──────┼────────────────────────────┤
│ 4       │ U32  │ status (0=OK, 1=failed)     │
└─────────┴──────┴────────────────────────────┘
```

失敗時 (status=1):

```
┌─────────┬──────┬────────────────────────────┐
│ バイト数 │ 型   │ フィールド                  │
├─────────┼──────┼────────────────────────────┤
│ 4       │ U32  │ reason-length               │
│ 可変    │ U8[] │ reason-string               │
└─────────┴──────┴────────────────────────────┘
```

## 5. 初期化フェーズ

### 5.1 ClientInit

```
クライアント → サーバ:
┌─────────┬──────┬────────────────────────────┐
│ バイト数 │ 型   │ フィールド                  │
├─────────┼──────┼────────────────────────────┤
│ 1       │ U8   │ shared-flag                 │
└─────────┴──────┴────────────────────────────┘
```

- `shared-flag != 0`: デスクトップを他のクライアントと共有
- `shared-flag == 0`: 排他アクセス（他のクライアントを切断）

### 5.2 ServerInit

```
サーバ → クライアント:
┌─────────┬──────────────┬──────────────────────┐
│ バイト数 │ 型           │ フィールド            │
├─────────┼──────────────┼──────────────────────┤
│ 2       │ U16          │ framebuffer-width     │
│ 2       │ U16          │ framebuffer-height    │
│ 16      │ PIXEL_FORMAT │ server-pixel-format   │
│ 4       │ U32          │ name-length           │
│ 可変    │ U8[]         │ name-string           │
└─────────┴──────────────┴──────────────────────┘
```

### 5.3 PIXEL_FORMAT構造体 (16バイト)

```
┌─────────┬──────┬────────────────────┬─────────────────────────┐
│ バイト数 │ 型   │ フィールド          │ 説明                     │
├─────────┼──────┼────────────────────┼─────────────────────────┤
│ 1       │ U8   │ bits-per-pixel     │ ワイヤ上のBPP (8,16,32)  │
│ 1       │ U8   │ depth              │ 有効ビット数              │
│ 1       │ U8   │ big-endian-flag    │ ピクセルのエンディアン     │
│ 1       │ U8   │ true-color-flag    │ トゥルーカラーかカラーマップか │
│ 2       │ U16  │ red-max            │ 赤の最大値 (2^N - 1)     │
│ 2       │ U16  │ green-max          │ 緑の最大値               │
│ 2       │ U16  │ blue-max           │ 青の最大値               │
│ 1       │ U8   │ red-shift          │ 赤の右シフト量            │
│ 1       │ U8   │ green-shift        │ 緑の右シフト量            │
│ 1       │ U8   │ blue-shift         │ 青の右シフト量            │
│ 3       │ -    │ padding            │ ゼロ埋め                  │
└─────────┴──────┴────────────────────┴─────────────────────────┘
```

**赤色値の抽出アルゴリズム:**
1. big-endian-flagに従いピクセルのバイトオーダーをスワップ
2. red-shiftビット分右シフト
3. red-maxとAND演算

**カラーマップモード** (true-color-flag = 0):
- ピクセル値はカラーマップのインデックス
- カラーマップはSetColorMapEntriesメッセージで設定

## 6. クライアント→サーバメッセージ

| 番号 | メッセージ名 | 用途 |
|------|-------------|------|
| 0 | SetPixelFormat | ピクセルフォーマットの設定 |
| 2 | SetEncodings | サポートするエンコーディングの宣言 |
| 3 | FramebufferUpdateRequest | フレームバッファ更新の要求 |
| 4 | KeyEvent | キーボード入力の送信 |
| 5 | PointerEvent | マウス/ポインタ入力の送信 |
| 6 | ClientCutText | クリップボードテキストの共有 |

**注意:** メッセージタイプ1は未使用（欠番）。

### 6.1 SetPixelFormat (タイプ0)

```
┌─────────┬──────────────┬────────────────────┐
│ バイト数 │ 型           │ フィールド          │
├─────────┼──────────────┼────────────────────┤
│ 1       │ U8           │ message-type [0]   │
│ 3       │ -            │ padding            │
│ 16      │ PIXEL_FORMAT │ pixel-format       │
└─────────┴──────────────┴────────────────────┘
```

- 以降のFramebufferUpdateのピクセルフォーマットを設定
- 送信直後にカラーマップは未定義になる
- サーバはクライアントが要求した任意のフォーマットをサポートしなければならない

### 6.2 SetEncodings (タイプ2)

```
┌─────────┬──────┬────────────────────────────┐
│ バイト数 │ 型   │ フィールド                  │
├─────────┼──────┼────────────────────────────┤
│ 1       │ U8   │ message-type [2]           │
│ 1       │ -    │ padding                    │
│ 2       │ U16  │ number-of-encodings        │
└─────────┴──────┴────────────────────────────┘

以下 number-of-encodings 回繰り返し:
┌─────────┬──────┬────────────────────────────┐
│ バイト数 │ 型   │ フィールド                  │
├─────────┼──────┼────────────────────────────┤
│ 4       │ S32  │ encoding-type              │
└─────────┴──────┴────────────────────────────┘
```

- 順序が優先度を示す（先頭ほど優先）
- 疑似エンコーディングも含む
- サーバはヒントを無視してRawで送信してもよい

### 6.3 FramebufferUpdateRequest (タイプ3)

```
┌─────────┬──────┬────────────────────────────┐
│ バイト数 │ 型   │ フィールド                  │
├─────────┼──────┼────────────────────────────┤
│ 1       │ U8   │ message-type [3]           │
│ 1       │ U8   │ incremental                │
│ 2       │ U16  │ x-position                 │
│ 2       │ U16  │ y-position                 │
│ 2       │ U16  │ width                      │
│ 2       │ U16  │ height                     │
└─────────┴──────┴────────────────────────────┘
```

- `incremental != 0`: 差分更新。サーバは変更部分のみ送信
- `incremental == 0`: 全更新。サーバは指定領域全体を送信（CopyRectは不可）
- サーバはクライアントがフレームバッファの内容をキャッシュしていると仮定
- 通常はインクリメンタル更新のみ必要
- 高速クライアントはリクエスト頻度を調整してトラフィックを制限すべき

**録画向け注意:** 録画時はこのメッセージを継続的に送信する必要がある。

### 6.4 KeyEvent (タイプ4)

```
┌─────────┬──────┬────────────────────────────┐
│ バイト数 │ 型   │ フィールド                  │
├─────────┼──────┼────────────────────────────┤
│ 1       │ U8   │ message-type [4]           │
│ 1       │ U8   │ down-flag                  │
│ 2       │ -    │ padding                    │
│ 4       │ U32  │ key (X Window keysym)      │

```

|--------|-------------|
| BackSpace | 0xff08 |
| Tab | 0xff09 |
| Return/Enter | 0xff0d |
| Escape | 0xff1b |
| Insert | 0xff63 |
| Delete | 0xffff |
| Home | 0xff50 |
| End | 0xff57 |
| Page Up | 0xff55 |
| Page Down | 0xff56 |
| Left/Up/Right/Down | 0xff51-0xff54 |
| F1-F12 | 0xffbe-0xffc9 |
| Shift (L/R) | 0xffe1/0xffe2 |
| Control (L/R) | 0xffe3/0xffe4 |
| Meta (L/R) | 0xffe7/0xffe8 |
| Alt (L/R) | 0xffe9/0xffea |

### 6.5 PointerEvent (タイプ5)

```
┌─────────┬──────┬────────────────────────────┐
│ バイト数 │ 型   │ フィールド                  │
├─────────┼──────┼────────────────────────────┤
│ 1       │ U8   │ message-type [5]           │
│ 1       │ U8   │ button-mask                │
│ 2       │ U16  │ x-position                 │
```

ボタンマスク:

| ビット | ボタン |

| 1 | 中ボタン |

| 3 | ホイール上 |

### 6.6 ClientCutText (タイプ6)

```
┌─────────┬──────┬────────────────────────────┐
│ バイト数 │ 型   │ フィールド                  │
├─────────┼──────┼────────────────────────────┤
│ 1       │ U8   │ message-type [6]           │
│ 3       │ -    │ padding                    │
│ 4       │ U32  │ length                     │
│ 可変    │ U8[] │ text (ISO 8859-1)          │
└─────────┴──────┴────────────────────────────┘
```

- テキストエンコーディング: ISO 8859-1 (Latin-1) のみ
- 改行: `\n` (0x0a) のみ。`\r` (0x0d) は使用しない

## 7. サーバ→クライアントメッセージ

| 番号 | メッセージ名 | 用途 |
|------|-------------|------|
| 0 | FramebufferUpdate | フレームバッファの変更を送信 |
| 1 | SetColorMapEntries | カラーマップパレットの更新 |
| 2 | Bell | ベル音を鳴らす |
| 3 | ServerCutText | クリップボードテキストの共有 |

### 7.1 FramebufferUpdate (タイプ0)

**ヘッダ (4バイト):**

```
┌─────────┬──────┬────────────────────────────┐
│ バイト数 │ 型   │ フィールド                  │
├─────────┼──────┼────────────────────────────┤
│ 1       │ U8   │ message-type [0]           │
│ 1       │ -    │ padding                    │
│ 2       │ U16  │ number-of-rectangles       │
└─────────┴──────┴────────────────────────────┘
```

**矩形ヘッダ (12バイト × number-of-rectangles):**

```
┌─────────┬──────┬────────────────────────────┐
│ バイト数 │ 型   │ フィールド                  │
├─────────┼──────┼────────────────────────────┤
│ 2       │ U16  │ x-position                 │
│ 2       │ U16  │ y-position                 │
│ 2       │ U16  │ width                      │
│ 2       │ U16  │ height                     │
│ 4       │ S32  │ encoding-type              │
```

- FramebufferUpdateRequestへの応答としてのみ送信
- 1つの更新で複数のリクエストを満たしてよい
- 矩形は通常互いに重ならないが、必須ではない

```
│ 2       │ U16  │ number-of-colors           │

```

## 8. エンコーディング

| 番号 | 名前 | 種類 | 状態 |
|------|------|------|------|
| 0 | Raw | 標準 | 必須サポート |
| 1 | CopyRect | 標準 | 推奨 |
| 2 | RRE | 標準 | 廃止予定 |
| 5 | Hextile | 標準 | 廃止予定 |
| 15 | TRLE | 標準 | 推奨 |
| 16 | ZRLE | 標準 | 推奨 |
| -239 | Cursor | 疑似 | オプション |
| -223 | DesktopSize | 疑似 | オプション |

### 8.1 Raw エンコーディング (タイプ0)

```
┌──────────────────────────────┬─────────┬────────────────────┐
│ バイト数                      │ 型      │ フィールド          │
├──────────────────────────────┼─────────┼────────────────────┤
│ width × height × bytesPerPixel │ PIXEL[] │ pixels            │
└──────────────────────────────┴─────────┴────────────────────┘
```

- 最もシンプルなエンコーディング
- 全クライアントが必須でサポート
- ピクセルは左→右、上→下のスキャン順
- クライアントが他のエンコーディングを要求しない場合のみサーバが使用すべき

### 8.2 CopyRect エンコーディング (タイプ1)

```
┌─────────┬──────┬────────────────────────────┐
│ バイト数 │ 型   │ フィールド                  │
├─────────┼──────┼────────────────────────────┤
│ 2       │ U16  │ src-x-position             │
│ 2       │ U16  │ src-y-position             │
└─────────┴──────┴────────────────────────────┘
```

- 既存のフレームバッファ位置を参照してコピー
- ウィンドウ移動やスクロールに有効
- ソース矩形は同じFramebufferUpdate内で先に更新されたピクセルを含むべきでない

### 8.3 RRE エンコーディング (タイプ2) [廃止予定]

Rise-and-Run-Length Encoding。2次元ランレングスエンコーディング。

**ヘッダ:**

```
┌─────────────────────┬──────┬────────────────────────────┐
│ バイト数              │ 型   │ フィールド                  │
├─────────────────────┼──────┼────────────────────────────┤
│ 4                   │ U32  │ number-of-subrectangles    │
│ bytesPerPixel       │ PIXEL│ background-pixel-value     │
└─────────────────────┴──────┴────────────────────────────┘
```

**サブ矩形 (× number-of-subrectangles):**

```
┌─────────────────────┬──────┬────────────────────────────┐
│ バイト数              │ 型   │ フィールド                  │
├─────────────────────┼──────┼────────────────────────────┤
│ bytesPerPixel       │ PIXEL│ subrect-pixel-value        │
│ 2                   │ U16  │ x-position                 │
│ 2                   │ U16  │ y-position                 │
│ 2                   │ U16  │ width                      │
│ 2                   │ U16  │ height                     │
└─────────────────────┴──────┴────────────────────────────┘
```

描画: まず背景色で塗りつぶし、その上にサブ矩形を重ね描き。

### 8.4 Hextile エンコーディング (タイプ5) [廃止予定]

矩形を16×16のタイルに分割し、各タイルをRRE風にエンコード。

**タイル順序:** 左→右、上→下

**タイルサブエンコーディングバイト (1バイト):**

| ビット | 名前 | 意味 |
|--------|------|------|
| 1 (0x01) | Raw | タイルは生ピクセルデータ |
| 2 (0x02) | BackgroundSpecified | 背景色が続く |
| 4 (0x04) | ForegroundSpecified | 前景色が続く |
| 8 (0x08) | AnySubrects | サブ矩形数が続く |
| 16 (0x10) | SubrectsColored | 各サブ矩形に色プレフィクス |

**サブエンコーディングのロジック:**

1. **Rawビットが立っている場合:** width×height個のピクセル値が続く。他のビットは無視
2. **BackgroundSpecified:** 背景色ピクセル (bytesPerPixel)
3. **ForegroundSpecified:** 前景色ピクセル (bytesPerPixel)。SubrectsColored=0を暗示
4. **AnySubrects:** サブ矩形数 (U8, 1バイト)
5. **SubrectsColored:** 各サブ矩形に色 (bytesPerPixel) が付く

**サブ矩形フォーマット:**

色ありの場合:
```
┌─────────────────────┬──────┬────────────────────────────┐
│ bytesPerPixel       │ PIXEL│ color                      │
│ 1                   │ U8   │ x-and-y (上位4bit=X, 下位4bit=Y) │
│ 1                   │ U8   │ w-and-h (上位4bit=W-1, 下位4bit=H-1) │
└─────────────────────┴──────┴────────────────────────────┘
```

色なしの場合:
```
┌─────────┬──────┬────────────────────────────────────────┐
│ 1       │ U8   │ x-and-y (上位4bit=X, 下位4bit=Y)       │
│ 1       │ U8   │ w-and-h (上位4bit=W-1, 下位4bit=H-1)   │
└─────────┴──────┴────────────────────────────────────────┘
```

**背景色/前景色の引き継ぎ:**
- 背景色は前のタイルから引き継がれる（前のタイルがRawでない限り）
- 前景色も引き継がれる（前のサブエンコーディングに依存する制約あり）

### 8.5 TRLE エンコーディング (タイプ15)

Tiled Run-Length Encoding。16×16タイルベースのRLEとパレット化。

**タイル順序:** 左→右、上→下

#### CPIXELフォーマット

コンパクトなピクセル表現:
- 通常: PIXELと同じ (bytesPerPixelバイト)
- 特殊3バイト形式: true-color-flag=1, bits-per-pixel=32, depth≤24で、R/G/Bが下位または上位3バイトに収まる場合

#### サブエンコーディングバイト (1バイト)

| 値 | タイプ | 内容 |
|----|--------|------|
| 0 | Raw | width×height個のCPIXEL値 |
| 1 | ソリッド | 単一CPIXEL値（タイル全体が同色） |
| 2-16 | パックドパレット | パレット + パック済みピクセルインデックス |
| 127 | パックドパレット再利用 | パック済みピクセルのみ（前回パレットを再利用） |
| 128 | プレーンRLE | ピクセル + ラン長ペア |
| 129 | パレットRLE再利用 | 前回パレットでのRLEラン |
| 130-255 | パレットRLE | パレット + インデックスによるRLEラン |

**パックドパレット (値2-16):**
- パレットサイズ分のCPIXELが先行
- ピクセルインデックスをビットパック
  - パレットサイズ2: 1ビット/ピクセル
  - パレットサイズ3-4: 2ビット/ピクセル
  - パレットサイズ5-16: 4ビット/ピクセル
- 各行はバイト境界にパディング

**RLEラン長エンコーディング:**
- ラン長 = 1 + 長さバイトの合計
- 255は継続を示す。255以外の値が最終
- 例: 長さ1=[0], 255=[254], 256=[255,0], 511=[255,255,0]

**パレットRLEラン:**
- 単一ラン (長さ1): 1バイトのパレットインデックス
- 複数ラン: インデックス+128プレフィクス、その後にラン長バイト

### 8.6 ZRLE エンコーディング (タイプ16)

TRLE + zlib圧縮。タイルサイズは64×64。

**ヘッダ:**

```
┌─────────┬──────┬────────────────────────────┐
│ バイト数 │ 型   │ フィールド                  │
├─────────┼──────┼────────────────────────────┤
│ 4       │ U32  │ length (zlib圧縮後のサイズ)  │
└─────────┴──────┴────────────────────────────┘
```

続いてlengthバイトのzlib圧縮タイルデータ。

**TRLE との差異:**
- タイルサイズが16×16ではなく64×64
- サブエンコーディング127と129は使用不可（パレット再利用なし）
- 1つのRFB接続で単一のzlibストリームを使用

**zlibの管理:**
- サーバは各矩形後にバイト境界までフラッシュ
- タイル間のフラッシュは不要
- クライアントはインクリメンタルにデコード可能

## 9. 疑似エンコーディング

疑似エンコーディングはピクセルデータを表すものではなく、プロトコル拡張を宣言する。
クライアントがSetEncodingsで宣言することで、サーバが対応する機能を提供する。

### 9.1 Cursor 疑似エンコーディング (タイプ -239)

**矩形ヘッダの特殊解釈:**
- x-position, y-position: カーソルのホットスポット
- width, height: カーソルの寸法

**データ:**

```
┌─────────────────────────────────┬─────────┬──────────────┐
│ バイト数                         │ 型      │ フィールド    │
├─────────────────────────────────┼─────────┼──────────────┤
│ width × height × bytesPerPixel  │ PIXEL[] │ cursor-pixels │
│ ceil(width/8) × height          │ U8[]    │ bitmask      │
└─────────────────────────────────┴─────────┴──────────────┘
```

**ビットマスク:**
- 1ピクセルあたり1ビット（左→右、上→下）
- 各行はバイト境界にパディング
- 1=有効ピクセル、0=透明

**目的:** クライアントがカーソルをローカルに描画し、体感パフォーマンスを向上。

### 9.2 DesktopSize 疑似エンコーディング (タイプ -223)

**矩形ヘッダ:**
- x-position, y-position: 無視
- width, height: 新しいフレームバッファサイズ
- データなし

**効果:**
- サーバはクライアントが以前のフレームバッファ内容を失ったと仮定
- 通常、完全なフレームバッファリフレッシュが発生
- 互換性: クライアントは旧サイズと新サイズの左上を保持

## 10. RFBバージョン差異

### 概要比較表

| 機能 | 3.3 | 3.7 | 3.8 |
|------|-----|-----|-----|
| セキュリティネゴシエーション | サーバ一方的 (U32) | クライアント選択 | クライアント選択 |
| None認証後のSecurityResult | なし | なし | あり |
| VNC認証失敗時のエラーメッセージ | なし | なし | あり |
| SecurityResult | VNC認証のみ | VNC認証のみ | 全セキュリティタイプ |

### RFB 3.3

- サーバがU32でセキュリティタイプを一方的に通知（ネゴシエーションなし）
- 値: 0 (失敗), 1 (None), 2 (VNC認証)
- None: SecurityResultなし → 直接初期化フェーズ
- VNC認証失敗: エラーメッセージなしで接続閉じ

### RFB 3.7

- セキュリティハンドシェイクはネゴシエーション方式（3.8と同じ形式）
- None: SecurityResultなし（3.3と同じ）
- VNC認証失敗: エラーメッセージなし（3.3と同じ）

### RFB 3.8

- セキュリティハンドシェイクはネゴシエーション方式
- 全セキュリティタイプでSecurityResultメッセージあり
- 失敗時は必ずエラー理由文字列を含む
- 最も一貫したエラーハンドリング

## 12. セキュリティに関する考慮事項

### プロトコルの制限

- **機密性保護なし**: 通信は平文
- **完全性保護なし**: 改ざんの検出不可
- **VNC認証は暗号学的に脆弱**

### 推奨事項

- IPsecまたはSSHトンネルを使用
- 安全な物理/仮想ネットワーク上で運用
- 暗号化のための拡張セキュリティタイプを検討

## 14. 実装上の注意点

### 録画用クライアントに関する考慮

1. **継続的なFramebufferUpdateRequest**: 録画中は常に更新を要求し続ける必要がある
2. **インクリメンタル更新の活用**: 差分のみ受信してフレームバッファに適用
3. **フレームバッファへの直接アクセス**: 録画エンジンがフレームバッファを読み取るためのアクセスが必要
4. **ピクセルフォーマットの選択**: 録画に適した形式（例: 32bpp BGRA）を設定

### エンコーディング優先度の推奨

クライアント実装では以下の順序でSetEncodingsを送信:
1. ZRLE (16) — 最高圧縮率
2. TRLE (15) — zlib不要の代替
3. Hextile (5) — レガシー互換
4. CopyRect (1) — ウィンドウ移動・スクロール効率化
5. Raw (0) — フォールバック（常にサポート）

加えて疑似エンコーディング:
- Cursor (-239) — ローカルカーソル描画
- DesktopSize (-223) — リサイズ対応
